# 维度 9：可观测性审查（指标 / 追踪 / 告警 / 健康检查）

日志（维度 8）回答"发生了什么"，可观测性回答"系统整体是否健康、趋势是否在变坏"。长期运行的服务（守护进程、交易心跳、relay 服务）默认启用本维度。

## 9.1 指标（Metrics）

- [ ] **四类黄金信号**：关键接口/任务是否有 延迟、流量、错误率、饱和度（队列深度/连接数/内存）指标？
- [ ] **业务指标**：核心域指标可度量（如交易系统：心跳轮次、下单成功/失败数、风控拦截数、盈亏快照）。
- [ ] **指标命名与标签**：命名规范（snake_case，带单位）、标签基数受控（禁止把 user_id/订单号当 label 导致基数爆炸）。
- [ ] **暴露方式**：metrics 端点（/metrics）或定时落库；端点是否需鉴权、是否误暴露公网。

## 9.2 追踪（Tracing）

- [ ] **关联 ID 贯穿**：request id / trace id / 会话 id / 心跳轮次号是否在跨进程、跨服务调用中传递（HTTP header、IPC 消息字段）？
- [ ] **关键跨度**：外部调用、DB 操作、队列消费是否形成可串联的 span/日志链，断链点在哪？
- [ ] **采样策略**：高频链路全量打点开销是否可控。

## 9.3 告警与巡检

- [ ] **告警条件**：ERROR 率突增、心跳停滞、队列积压、余额/额度异常等是否有告警或至少可被外部巡检发现？
- [ ] **告警可读**：告警内容含定位信息（哪个实例、哪个实体、最近上下文），非 "something wrong"。
- [ ] **免告警疲劳**：预期内抖动（重试成功、短暂断连自愈）不应触发 ERROR 级告警。

## 9.4 健康检查与生命周期

- [ ] **健康端点**：liveness（进程活着）与 readiness（依赖就绪、可接流量）分离；readiness 检测必须与被检对象生命周期匹配（典型反例：检测仅在目标进程内存活的服务，进程外探测必然假阴性）。
- [ ] **优雅退出**：SIGTERM/SIGINT 时是否停止接新任务、完成在途任务、释放锁与连接、记录退出原因与 exit code？
- [ ] **崩溃可诊断**：未捕获异常/退出是否有最后日志（fatal log + stack），exit code 语义是否区分（配置错误 / 依赖不可用 / 内部 bug）。
- [ ] **锁与单实例**：文件锁/端口锁冲突时日志明确（谁在占用、持有了多久），便于排查 lock conflicts。

## 判定级别

- P1：核心服务无健康检查、无退出日志、关键告警缺失导致故障不可发现；trace id 断链导致跨服务问题无法定位。
- P2：黄金信号指标缺失、标签基数隐患、告警级别乱用。
- P3：指标命名不规范、采样可优化。
