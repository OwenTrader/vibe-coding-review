# 维度 3：安全边界审查

## 3.1 注入与输入处理

- [ ] **SQL/查询注入**：拼接 SQL / NoSQL 查询字符串？ORM 的 raw query 是否参数化？
- [ ] **XSS**：`dangerouslySetInnerHTML` / `v-html` / 直接 `innerHTML` 赋值的用户可控内容是否经过消毒（sanitize）？
- [ ] **命令注入**：`child_process.exec` / `os.system` / `subprocess(shell=True)` 的参数是否含用户可控输入？改用参数数组形式（execFile / shell=False）。
- [ ] **路径穿越**：文件读写路径是否拼接了外部输入？是否校验规范化后路径仍在允许目录内？
- [ ] **SSRF**：服务端代发的 URL 是否校验协议/内网地址白名单？

## 3.2 认证与授权

- [ ] **鉴权缺失**：新增 API 路由 / RPC 方法 / 页面是否都经过认证中间件？尤其注意"只藏入口不锁接口"的假防护。
- [ ] **越权（IDOR）**：按 ID 取数据时是否校验资源归属当前用户/租户？
- [ ] **权限最小化**：管理端能力与普通用户能力是否隔离？前端隐藏按钮但后端不校验 = P0。
- [ ] **会话与令牌**：token 过期、刷新、登出失效逻辑是否完整？令牌是否出现在 URL / 日志中？

## 3.3 敏感信息

- [ ] **硬编码密钥**：代码中的 API key、密码、token、私钥（应走环境变量/密钥管理）。检查 diff 中新增字符串常量。
- [ ] **日志泄密**：密码、token、身份证号、银行卡号、完整交易凭证是否被写入日志？（与日志维度联动）
- [ ] **错误信息泄密**：返回给前端的错误是否暴露堆栈/SQL/内部路径？
- [ ] **数据落地**：敏感数据是否明文写入本地文件/缓存/localStorage？

## 3.4 边界与暴露面

- [ ] **网络绑定**：服务是否误绑 `0.0.0.0` 暴露到公网/局域网？调试端口（如 9229、devtools）是否在生产开放？
- [ ] **CORS**：是否 `Access-Control-Allow-Origin: *` 且同时允许携带凭据？
- [ ] **Electron 特有**：`nodeIntegration`/`contextIsolation` 配置是否安全？preload 暴露的 API 是否最小化？渲染进程能否直接执行系统命令？
- [ ] **文件上传**：类型/大小/扩展名校验是否在服务端做？存储位置是否不可执行？
- [ ] **重定向**：open redirect（未校验的 redirect 参数）？
- [ ] **速率限制**：登录、验证码、下单、支付等敏感接口有无防刷/限流？

## 判定级别参考

- P0：可未授权访问数据/执行操作、注入、硬编码生产密钥、越权读写。
- P1：敏感信息进日志、CORS 过宽、调试面暴露。
- P2：缺少速率限制、错误信息过详细。
