# 高级审查维度（维度 22-48）

本文件覆盖架构、数据、可靠性、安全深化、发布交付、前端深度、演进能力七大类高级维度。标注「边界」的维度与既有维度存在重叠：审查时以既有维度为主入口，本维度只补充增量检查项，避免同一问题重复报告。

## 架构与设计

### 维度 22：架构合理性
- [ ] 模块边界清晰、职责单一；分层方向（UI → 应用 → 领域 → 基础设施）无倒置。
- [ ] 依赖方向：底层不依赖上层；无循环依赖（import/require cycle，可用 madge/dependency-cruiser/pydeps 验证）。
- [ ] 跨模块通信走显式接口/事件，不直接读对方内部实现或私有状态。
- [ ] 新代码放对层：业务规则不在 UI/路由层，IO/网络不在领域层。
- [ ] 公共能力下沉共享模块，而非各模块各抄一份。
- [ ] 服务/进程边界与团队所有权、部署单元匹配。

### 维度 23：业务逻辑正确性
- [ ] 对照需求/PRD 逐条验证业务规则实现（不止"能跑"，要"算得对"）。
- [ ] 状态转换穷举：遗漏、冲突、反常路径（如 已完成→待支付）。
- [ ] 计算公式与业务口径（金额、费率、时间窗口、账期）与文档一致。
- [ ] 边界业务规则：首单、最后一件库存、跨日/跨月切换、闰年/时区。
- [ ] 业务不变量（invariant）有断言或测试守护（如余额≥0、仓位=Σ成交）。
- [ ] 旁路路径：admin 接口、运维脚本、迁移代码是否绕过业务校验直接写库。

## 状态与数据

### 维度 24：状态管理
- [ ] 状态来源单一（single source of truth），无多份真相互相覆盖。
- [ ] 前端：本地 state / store / URL / 服务端状态的同步策略清晰。
- [ ] 缓存状态：过期、失效、乐观更新失败后的回滚。
- [ ] 状态机完整性：定义、迁移表、非法迁移拦截、终态处理。
- [ ] 过期状态清理：会话、锁、临时令牌、僵尸任务。
- [ ] 重置路径：退出登录/切换账户后旧状态完全清理。

### 维度 26：数据一致性（边界：维度 5 审单实体 CRUD，本维度审跨系统）
- [ ] DB/缓存/队列/搜索索引/第三方系统之间的同步路径与失败窗口。
- [ ] 写策略明确：写穿/写回、失效顺序（先 DB 后缓存）。
- [ ] 对账机制：定期校验、差异告警、修复工具。
- [ ] 最终一致性的用户可见窗口可接受且有说明。
- [ ] 跨系统事务：Saga/补偿/幂等消费者。
- [ ] 跨系统事件顺序依赖有时钟/序号保证。

### 维度 34：数据生命周期
- [ ] 创建→使用→缓存→归档→删除→彻底清理 全链路有 owner。
- [ ] 各类数据保留期明确（含日志、备份、导出文件）。
- [ ] 删除完整性：主库+副本+缓存+索引+备份+第三方同步级联清除。
- [ ] 归档数据的可读性与恢复路径。
- [ ] 临时数据（上传临时文件、中间产物）定期清理。

### 维度 38：数据库设计（边界：维度 5 审操作完整性，本维度审结构设计）
- [ ] Schema：字段类型/长度/NULL 性合理，范式与反范式取舍有据。
- [ ] 索引匹配查询模式，无冗余索引；慢查询有执行计划验证。
- [ ] 约束（唯一/外键/CHECK）在 DB 层兜底，不只靠应用层。
- [ ] 外键与级联行为显式设计。
- [ ] Migration：幂等、可回滚、大表变更分批/在线 DDL 不锁表。
- [ ] 增长预估：大表分区/归档策略。

### 维度 45：数据迁移
- [ ] 新旧代码对老数据的读写兼容。
- [ ] 迁移脚本幂等：重复执行安全。
- [ ] 失败恢复：中断可续跑、部分失败可定位。
- [ ] 数据验证：迁移前后计数/抽样比对。
- [ ] 大表迁移：分批、限速、业务低峰执行。
- [ ] 迁移失败的回退方案。

### 维度 31：灾备与数据恢复
- [ ] Backup：范围、频率、加密、异地/离线副本。
- [ ] Restore：流程文档化、定期演练、恢复后一致性校验。
- [ ] RPO/RTO 目标明确且实测可达。
- [ ] 误删恢复：软删窗口、回收站、时间点恢复（PITR）。
- [ ] 灾难场景覆盖：整库丢失、机房/区域故障、备份文件本身损坏。

## 缓存与前端状态

### 维度 27：缓存策略（边界：维度 11 审性能收益，本维度审正确性）
- [ ] Cache Key 设计含版本/租户/权限维度，避免串数据。
- [ ] TTL 与主动失效结合；写路径失效完整（含关联 key）。
- [ ] 三穿防护：穿透（空值缓存/布隆）、击穿（热点 key 互斥重建）、雪崩（TTL 加抖动/多级缓存）。
- [ ] 脏数据窗口评估与监控。
- [ ] 缓存不可用时回源有限流，不打垮 DB。
- [ ] 缓存结构变更后旧缓存数据兼容（序列化版本）。

### 维度 43：前端交互状态（边界：维度 1 审视觉一致性，本维度审状态覆盖完整性）
- [ ] 每个异步操作六态覆盖：Idle / Loading / Success / Empty / Error / Pending。
- [ ] Optimistic Update：失败回滚与冲突处理。
- [ ] Disabled：防重复提交、权限不足置灰（后端仍须校验）。
- [ ] 竞态：快速切换/连续输入时过期响应丢弃（abort/序号比对）。
- [ ] 中断恢复：刷新/返回后状态可恢复。
- [ ] 骨架屏/渐进加载策略。

## 可靠性与韧性

### 维度 28：异步任务与消息队列
- [ ] 消费幂等：重复投递不产生重复副作用。
- [ ] 重试策略：次数、退避、可重试错误分类。
- [ ] 死信队列：存在、有监控、有重放/人工处理路径。
- [ ] 消息顺序：需要顺序的场景有分区/单消费者保证。
- [ ] 防丢失：生产者确认、消费者 ack 在处理成功之后。
- [ ] 长任务心跳与卡死检测（看门狗）。
- [ ] 积压监控与扩容路径。

### 维度 29：容灾与故障恢复
- [ ] 依赖服务不可用时：超时、熔断、降级、安全默认值。
- [ ] DB 故障：只读降级、重连退避、启动期依赖不可用的行为。
- [ ] 故障后状态重建路径（日志/快照/对账）。
- [ ] 数据损坏的人工介入工具（修复脚本/控制台）。
- [ ] 恢复流程文档化且演练过。

### 维度 30：限流与资源保护（边界：维度 3.4 审安全防刷，本维度审容量保护）
- [ ] Rate Limit：按用户/IP/租户分级，敏感接口单独配额。
- [ ] 并发上限：信号量/队列控制，无无界并发。
- [ ] 连接池/线程池大小有界且与下游容量匹配。
- [ ] 请求体/上传文件/分页大小上限。
- [ ] 超时体系：每跳超时 < 上层超时，全链路有超时预算。
- [ ] 资源耗尽防御：内存队列有界、磁盘写入限速。

### 维度 40：第三方服务依赖
- [ ] 每个外部依赖的 SLA 假设与故障模式清单。
- [ ] 超时、重试（幂等前提下）、熔断、Fallback 齐备。
- [ ] 配额监控：接近限额有告警。
- [ ] Webhook 安全：签名校验、重放防护、幂等处理。
- [ ] 依赖故障时的降级体验与用户提示。
- [ ] 供应商锁定评估与替代方案。

### 维度 41：任务调度
- [ ] Cron 表达式正确，时区明确（UTC/本地写进注释）。
- [ ] 多实例防重复执行：分布式锁/租约。
- [ ] 错过补偿：实例停机期间 missed run 的补跑策略。
- [ ] 周期重叠：上一轮未结束下一轮不重复起（或显式允许并发）。
- [ ] 可观测：上次成功时间、耗时、失败告警（与维度 9 联动）。
- [ ] 手动触发与重跑工具。

### 维度 42：资源生命周期（边界：维度 11 审性能影响，本维度审释放正确性）
- [ ] 文件句柄/连接/流：try-finally 或 with 保证释放。
- [ ] 线程/协程：退出路径、join/取消。
- [ ] Timer/Interval：组件卸载/任务结束时清理。
- [ ] Subscription/事件监听：subscribe/unsubscribe 成对。
- [ ] 临时文件：含异常路径在内的清理。
- [ ] 锁：所有分支获取-释放配对，含超时与死锁规避。

## 安全深化

### 维度 25：权限与身份认证（边界：维度 3.2 审攻击面，本维度审模型设计）
- [ ] 认证机制：token 签发/刷新/吊销、会话固定防护、多设备策略。
- [ ] 授权模型：RBAC/ABAC 与数据权限（行级/字段级）显式设计。
- [ ] 资源所有权校验落实在每个读/写端点（非仅列表过滤）。
- [ ] 权限变更即时生效：角色调整后旧 token/缓存权限的失效窗口可控。
- [ ] 默认拒绝：新端点/新资源默认无权限，需显式授予。
- [ ] 权限矩阵文档化且与代码一致。

### 维度 32：安全输入输出（边界：维度 3.1 审注入点，本维度补全攻击类型）
- [ ] CSRF：状态变更请求有 token / SameSite / Origin 校验。
- [ ] 反序列化：不信任数据的类型白名单，禁用危险反序列化器。
- [ ] 模板注入、NoSQL 操作符注入、LDAP/XPath 注入。
- [ ] 输出编码按上下文（HTML/JS/CSS/URL 分别处理）。
- [ ] 文件内容魔数校验，不只信扩展名。
- [ ] XXE：XML 解析禁用外部实体。

### 维度 33：Secrets 管理（边界：维度 3.3 审泄露点，本维度审管理生命周期）
- [ ] 存储：vault/KMS/环境变量，不入代码库、不进镜像层。
- [ ] 轮换：定期轮换机制 + 泄露后的紧急轮换流程。
- [ ] 最小权限、按环境隔离（dev 密钥访问不到 prod 资源）。
- [ ] CI/CD 注入与日志 mask（防止打印环境变量时泄密）。
- [ ] 仓库 secret 扫描（gitleaks/trufflehog）接入 CI。
- [ ] 证书有效期监控与更新流程。

## 交付与发布

### 维度 35：Feature Flag / 灰度发布
- [ ] Flag 生命周期：创建→灰度→全量→清理（防止 flag 债堆积）。
- [ ] 默认值安全：flag 服务不可用时走安全保守分支。
- [ ] 灰度规则集中管理（按用户/租户/百分比），不散落代码里。
- [ ] 关 flag 即可回退，无需发版。
- [ ] 新旧路径并存期的数据兼容。
- [ ] flag 当前生效值进日志/metrics（可观测）。

### 维度 36：部署与发布
- [ ] 构建可重现、产物版本化、环境逐级提升（dev→staging→prod）。
- [ ] 配置外部化，同一产物跨环境部署。
- [ ] Migration 与代码的发布顺序正确（先兼容迁移，后部署）。
- [ ] 启动顺序与依赖就绪等待（不依赖"碰巧起得来"）。
- [ ] 零停机：滚动/蓝绿/金丝雀 + 健康检查摘流量。
- [ ] 发布窗口与变更冻结策略。

### 维度 37：可回滚性
- [ ] 代码可回滚：历史产物保留、一键回退。
- [ ] DB Schema 可回滚：迁移有 down；破坏性变更分阶段（先加后删）。
- [ ] 配置版本化可回滚。
- [ ] 数据结构变更：新旧格式并存期双写/兼容读。
- [ ] 回滚演练过，回滚决策人明确。

### 维度 39：API 版本与兼容策略（边界：维度 14 审接口设计，本维度审版本演进）
- [ ] Breaking Change 有清单与评审。
- [ ] 版本策略明确（URL 版本 / Header / Sunset 头）。
- [ ] 旧客户端兼容期与强制升级机制。
- [ ] 字段废弃路径：deprecated 标记 → 双写期 → 下线。
- [ ] 契约测试防止意外破坏（如 Pact/schema diff）。

## 演进能力

### 维度 46：技术债务
- [ ] TODO/FIXME/HACK 盘点：有归属与期限，非永久寄存。
- [ ] 临时代码/workaround 有跟进任务，非"临时变永久"。
- [ ] Deprecated API 与旧实现的清理进度。
- [ ] 为旧版本保留的兼容分支是否已可下线。
- [ ] 同一能力多份实现的收敛计划。
- [ ] 债务显性化：记录在 issue/文档而非口头相传。

### 维度 47：可维护性（边界：维度 2.3 审代码级，本维度审工程级）
- [ ] 修改成本：改一条业务规则需要触动的文件数（散弹式修改 = 坏味道）。
- [ ] 耦合程度：模块间接口窄，实现细节不外泄。
- [ ] 抽象合理性：不过度抽象（三层包装调一行）也不缺抽象。
- [ ] 知识集中度：关键模块是否只有一人懂（巴士因子）。
- [ ] 新人上手成本：文档、示例、可一键运行的开发环境。

### 维度 48：可扩展性
- [ ] 新功能是"加代码"还是"改代码"（开闭原则；策略表/插件点 vs 硬编码 if 链）。
- [ ] 新租户/多租户：数据与配置隔离模型可扩展。
- [ ] 数据规模：10x/100x 数据量下的瓶颈点（单表、单文件、单队列）。
- [ ] 新业务规则接入成本（如新增交易品种/新审批类型要改几处）。
- [ ] 水平扩展：无状态化，共享状态外置（DB/缓存/队列）。
