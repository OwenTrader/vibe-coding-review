# 维度 7：日志规范审查（关键路径覆盖 + 防无限堆积）

两条铁律：**关键功能必须有日志**（出问题能定位），**日志不能无限堆积**（磁盘/内存/控制台不能被撑爆）。两者同时满足才算合格。

## 7.1 关键路径覆盖检查项

以下位置必须有日志，缺失即 P1：

- [ ] **入口与出口**：API 请求、RPC/IPC 调用、定时任务、CLI 命令的开始与结束（含耗时、结果状态）。
- [ ] **状态变更**：写库、下单、支付、配置修改、权限变更等不可逆/高价值操作，记录 who/when/what/before→after（注意脱敏）。
- [ ] **决策分支**：策略引擎、风控拦截、自动重试、降级开关等"为什么走这条路"的决策依据（输入摘要 + 命中规则 + 输出）。
- [ ] **异常现场**：catch 块必须记录 error message + stack + 上下文（请求 id、操作对象 id），禁止空 catch 或只 `console.log('error')`。
- [ ] **外部依赖调用**：调用第三方/下游服务的请求摘要、响应码、耗时；失败重试的次数与退避。
- [ ] **生命周期事件**：进程启动/退出、连接建立/断开、锁获取/释放、心跳轮次（含轮次号，便于发现空转）。

## 7.2 防无限堆积检查项

- [ ] **轮转机制**：写文件的日志必须配置轮转——按大小（如单文件 10-50MB）或按天滚动，并设**保留上限**（max files / max days）。裸 `FileHandler` / `fs.createWriteStream` 无上限追加 = P1。推荐：Python `RotatingFileHandler`/`TimedRotatingFileHandler`，Node `winston-daily-rotate-file`/`pino` + transport，Go `lumberjack`。
- [ ] **总量上限**：日志目录总大小或文件数有硬上限；保留时长明确（如 7/30 天）。临时 debug 日志单独文件且更短保留。
- [ ] **级别控制**：DEBUG/TRACE 级别在生产可关闭；禁止在热路径（循环内、每 tick、每帧）无级别控制地输出。
- [ ] **高频日志采样/聚合**：心跳、轮询、行情推送类高频事件不得逐条写盘——采用计数聚合（"本轮处理 N 条"）、N 取 1 采样、或仅在异常时输出。
- [ ] **内存缓冲有界**：内存 ring buffer / 日志队列必须定长，溢出丢弃最旧（push-and-discard），禁止无界 append。
- [ ] **结构化输出**：机器可读（JSON 或 key=value），包含 timestamp、level、module、msg；禁止裸 print 满天飞。
- [ ] **stdout 兜底**：长期运行的服务若只输出到 stdout，需确认托管方（systemd/pm2/docker）有日志切割，否则等价于无轮转。
- [ ] **数据库日志上限**：数据库**慢查询日志与错误日志**是否有大小 / 时间上限？慢查询阈值是否配置（PostgreSQL `log_min_duration_statement`、MySQL `slow_query_log` + `long_query_time`），且不会因阈值过松而**无上限落盘**写满磁盘？DB 日志目录 / 表空间是否有保留与清理策略（含 `log_rotation_size`、`log_directory` 清理）？审「代码里的日志」时不要漏掉**数据库自身的日志**。
- [ ] **云日志管道上限**：使用云日志服务（CloudWatch Logs / Loki / ELK / 腾讯云 CLS 等）时，是否设置**采集上限、索引策略、保留期与定期清理**？是否存在"全量索引 + 永久保留"导致查询与成本双双失控（全量索引大字段、无过滤采集）。云原生日志管道同样属于"无限堆积"风险面。

## 7.3 日志内容质量

- [ ] **脱敏**：密码、token、密钥、身份证号、完整账号凭证不入日志（与安全维度联动，命中即 P0/P1）。
- [ ] **可追溯**：有关联 ID（request id / trace id / 会话 id / 轮次号）串联一次操作的各条日志。
- [ ] **可检索**：错误日志包含足够定位的上下文（哪个实体、哪个输入），而非 "something went wrong"。
- [ ] **级别恰当**：ERROR=需要介入，WARN=异常但可自愈，INFO=关键业务事件，DEBUG=排查细节。 ERROR 滥用于普通校验失败会淹没真告警。

## 输出要求

每个日志发现按三类标注：**缺失**（关键路径无日志）、**堆积风险**（无轮转/无上限/高频无聚合）、**质量**（泄密/无上下文/级别乱用），并给出具体接入点与改造示例。
