# 维度 1：UI/UX 样式一致性 + 公共样式抽离

适用：含界面层的项目（Web / Electron / Flutter / 小程序）。审查前必须先盘点项目的既有样式资产：设计 token（CSS 变量 / theme 文件 / Tailwind config）、公共组件库、全局样式表。

## 1.1 样式一致性检查项

- [ ] **颜色**：是否存在硬编码色值（hex/rgb）绕过设计 token？同一语义色（主色、危险色、成功色）是否出现多个近似但不相同的色值？
- [ ] **间距与尺寸**：margin/padding/gap 是否遵循统一刻度（4px/8px 基数或 theme spacing）？有无 13px、17px 这类"随手拍"数值？
- [ ] **字体**：font-size / font-weight / line-height 是否与全局排版规范一致？有无局部覆写导致同层级标题字号不一致？
- [ ] **圆角 / 阴影 / 边框**：卡片、按钮、输入框的圆角与阴影是否统一？
- [ ] **交互态**：hover / active / focus / disabled / loading 状态是否齐备且风格一致？focus 可见性（无障碍）是否被 `outline: none` 干掉且无替代？
- [ ] **响应式**：断点使用是否一致？有无写死 px 宽度导致小屏溢出/大屏拉伸？
- [ ] **深色模式/主题切换**（若项目支持）：新增样式是否走了主题变量，还是在暗色下会"露白"？
- [ ] **文案一致性**：同一动作在不同页面的命名（"删除" vs "移除" vs "Delete"）、确认弹窗文案、空态文案是否统一？
- [ ] **反馈完整性**：用户操作后是否有成功/失败反馈（toast/提示）？耗时操作是否有 loading？ destructive 操作是否有二次确认？
- [ ] **错误信息不得明文暴露给用户**：禁止把原始异常文本、traceback、技术错误串、内部代码直接呈现给终端用户（toast / 弹窗 / 页面 / 终端输出），典型反例：`llm transport error: [WinError 10060]`、`ECONNREFUSED 127.0.0.1:5432`、`TypeError: Cannot read properties of undefined`、SQL 报错原文。要求：
  - **已知错误码/异常类型 → 转换为用户可理解的业务语言**（例：连接超时 → "网络连接失败，请检查网络或稍后重试"；鉴权失败 → "登录已过期，请重新登录"；配额用尽 → "今日额度已用完"），并给出**可执行的下一步**（重试 / 重登 / 联系客服）。
  - **未知错误码 → 降级为简要提示**（如"操作失败，请稍后重试"），并附**可追溯的引用码**（如 `错误码 E-1007` 或短 request id），便于用户报障时客服定位；**不得**把原始堆栈拼进提示。
  - **原始错误只进日志**（含堆栈与上下文），与用户可见文案分离（与维度 7 联动）；文案由集中映射表/错误码字典产出，而非各调用点 `catch (e) { toast(e.message) }` 直接透传。
  - 排查方法：检索 `toast(` / `showMessage(` / `alert(` / `Message.error` / `print(e)` / `console.error` 直出路径，确认渲染的是否为 `e.message` / `str(e)` / `String(err)` 等原始值。

## 1.2 公共样式/组件抽离检查项

- [ ] **重复样式块**：≥2 处出现相同/高度近似的 class 组合或 style 块，应抽为公共 class、CSS 变量或组件。
- [ ] **重复组件**：按钮、卡片、弹窗、表单行、空态、表格等是否存在多个"长得差不多"的本地实现，而未复用既有公共组件？
- [ ] **内联样式**：`style="..."` 内联样式是否可避免？（动态计算值除外）
- [ ] **魔法样式值**：z-index 有无失控（9999、99999）？应建立层级规范（如 toast > modal > dropdown > header）。
- [ ] **样式作用域**：全局样式污染（未加作用域的元素选择器如 `div { ... }`）是否会影响其他页面？
- [ ] **图标与资源**：同一图标是否引用了多个不同来源/尺寸的资源文件？

## 判定级别参考

- P1：交互反馈缺失导致用户无法感知操作结果；destructive 操作无确认；主题下明显破版；**错误信息明文暴露给用户**（原始异常/traceback/内部错误串直出，含泄露内部地址、端口、库版本、SQL、密钥片段的风险）。
- P2：硬编码色值/间距、重复组件未抽离、文案不一致；错误提示虽有转换但措辞含糊、无可执行下一步或无可追溯引用码。
- P3：内联样式、可进一步抽象的样式模式。

## 输出要求

每个"应抽离"发现需给出：重复出现的文件:行号清单、建议抽取到的目标位置（既有公共文件或新建）、以及抽取后的调用方式示意。
