# 审查报告模板

按以下结构输出审查报告。语言：中文。所有发现必须有代码证据（文件:行号 + 片段）。

---

## 审查概览

| 项 | 内容 |
|----|------|
| 审查范围 | （commit/diff/目录/文件清单） |
| 分支 / 改动状态 | （分支名；是否有未提交改动） |
| 技术栈 | （语言/框架/样式方案/数据库） |
| 审查维度 | （本次启用的维度列表） |
| 审查时间 | |
| 审查假设 | （本次未获取到、按推断处理的输入，如"假定设计 token 来源为 X"） |
| 总体结论 | ✅ 可合并 / ⚠️ 修复 P0-P1 后可合并 / ❌ 存在阻断问题 |

## 问题统计

| 级别 | 数量 |
|------|------|
| P0 阻断 | n |
| P1 严重 | n |
| P2 一般 | n |
| P3 建议 | n |

## 审查覆盖度声明

**必须输出**，用于区分"查过没问题"与"根本没查"。每个启用维度标注三态；未跑的维度必须给出原因。每个检查项在明细中同样标注 `已检查` / `发现问题` / `不适用`。

| 维度 | 状态 | 检查项 | 说明 |
|------|------|--------|------|
| 1 UI/UX 一致性 | 已检查 | 12/12 | 无发现 |
| 2 代码质量 | 发现问题 | 6/8 | 见 P1-2、P2-1 |
| 15 隐私与数据合规 | 不适用 | — | 无个人数据 |
| 29 容灾与故障恢复 | 未跑 | — | 非上线场景，经用户确认跳过 |
| （其余）| … | … | … |

- 覆盖度：本次实跑 **N / M** 个维度（M = 本次按项目类型应启用的维度总数）。
- 未跑维度：`…`（原因），`…`。

## 误报反馈（复审与收敛用）

用户驳回某条发现时，在此记录裁定与归类，供后续审查收敛（同类误报不再报出）。

| 发现编号 | 用户裁定 | 归类 | 收敛动作 |
|----------|----------|------|----------|
| P2-3 | 驳回 | 项目约定例外（该处硬编码为既有规范） | 同项目复审不再报该模式 |
| P1-4 | 驳回 | 证据不足 | 下次需补调用链证据再报 |

**归类三选一**：
- `规则过严`：检查项对当前项目不适用 → 该项目内关闭该检查项并记录。
- `证据不足`：结论正确但证据不充分 → 保留为"待验证"，下次补证。
- `项目约定例外`：违反通用规范但属项目既有约定 → 记入例外清单，后续不再报。

> 例外清单随报告交付，供**同一项目**下次审查加载（项目约定例外不跨项目套用）。未反馈的发现默认视为有效。
